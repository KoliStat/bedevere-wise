# Changelog

## v0.14-and-this

- [Breaking] **`BedevereApp` requires `options.backend`.** The app shell no longer constructs a default `DuckDBService` when you omit a backend — that hidden default was the last static edge pulling DuckDB-WASM into every consumer of the shell. Pass the engine explicitly: `import { DuckDBService } from "@kolistat/bedevere-wise/duckdb"` and hand it `new DuckDBService()` (the in-browser default), or an `IpcBackend` / remote relay. The standalone web app and the desktop renderer already injected their backend, so nothing user-facing changed; only the zero-arg `new BedevereApp(el, ver)` path is gone. The gate that decides whether to run the WASM extension probe now keys off `backend.id === "duckdb-wasm"` instead of `instanceof DuckDBService`, so the shell module never references the `DuckDBService` value.
- [Feature] **New `@kolistat/bedevere-wise/app` sub-entry — the app shell, backend-agnostic, zero DuckDB-WASM.** `BedevereApp` + `TabManager` / `ControlPanel` / `StatusBar` / `CommandBar` + the `PersistenceService` singleton now ship from a dedicated `/app` entry that pulls **no** DuckDB-WASM. A host that brings its own engine (bedevere-desktop's native DuckDB over IPC, a remote relay) imports the full UI from `/app` and never bundles the ~3 MB of DuckDB worker assets. The back-compat root entry still re-exports `/duckdb`, so importing from the package root continues to pull the WASM chain.
- [Enhanced] **DuckDB-WASM loads lazily.** `DuckDBService.initialize()` now dynamic-`import()`s the `@duckdb/duckdb-wasm` module and its four worker `?url` URLs instead of importing them at module top level, and the shared `duckDBService` singleton moved out of `DuckDBService.ts` into the app entry points. Net effect: the engine module is side-effect-free and tree-shakeable, the web app fetches the DuckDB worker bytes during init rather than up front, and non-WASM embedders drop them entirely. bedevere-desktop's renderer bundle fell from ~4.5 MB to ~1.8 MB.
- [Security] **Quote untrusted SQL identifiers (table + column names) via `quoteIdent`.** Column names (read from a file's header / schema) and table names (derived from a filename) were interpolated into generated SQL as `"${name}"` without escaping an embedded `"`, so a crafted file could break out of the identifier quotes — most serious on the IPC / native backend, where that SQL runs against a native DuckDB with filesystem reach. Every identifier sink now routes through `quoteIdent` (which doubles embedded quotes): the per-column stats / sort / projection / filter queries (`DuckDBDataProvider`, `FilteredDuckDBDataProvider`, `ColumnFilterManager`), the Parquet / Excel / Stat import `CREATE TABLE`s, `DuckDBService.executeQueryAsDataProvider`, and `AliasManager`'s `ALTER TABLE … RENAME`. Filter *values* and file-path *literals* were already escaped. For ordinary names the emitted SQL is byte-identical; only `"`-bearing names change. Added a regression test (`sqlInjection.test.ts`).
- [Security] **Web hardening — CSP, embed dataset scheme allowlist, chart action menu.** Added a Content-Security-Policy to the deployed app and the `/embed` route (`public/_headers`): `script-src 'self' 'wasm-unsafe-eval'` (no `'unsafe-inline'`), `worker-src 'self' blob:`, `object-src 'none'`, `base-uri 'self'`, and scoped `frame-ancestors` (the main app forbids framing; `/embed` allows the blog) — replacing the obsolete `X-Frame-Options: ALLOW-FROM`. Vite's inline modulepreload polyfill is disabled (`build.modulePreload.polyfill: false`) so the strict `script-src` holds with no inline scripts in the built HTML. The `/embed` dataset loader now requires `https:` (http only for localhost), closing the SSRF-shaped fetch an untrusted host page could trigger via `?dataset=`. The Vega chart action menu drops its *source* / *compiled* / *Open in Vega Editor* items (export kept). Note: the CSP should be smoke-tested on a preview deploy before prod (app load, query, chart render, URL-dataset import, cross-origin embed).
- [Docs] **`docs/backend-protocol.md` §2 (Transport) updated** for the desktop sidecar hardening: the IPC token is delivered out of band (injected `window.__BEDEVERE_IPC__` global, not the URL), the shell validates `Origin` + `Host` on the WebSocket upgrade (DNS-rebinding defense), and inbound frames are capped — superseding the old "token in URL query string" + "no origin check" description.
- [Bug-fix] **`table_one` (and the other stats_duck aggregates) work again on the web.** They crashed in the browser / embeds with `TypeError: r is not a function` at the wasm boundary. The cause was an **i64 ABI mismatch**, not a DuckDB version: the bundled stats_duck WASM was built with `-sWASM_BIGINT=0` (i64 legalized to i32 pairs) while `@duckdb/duckdb-wasm` is built `WASM_BIGINT=1` (native i64), so `table_one`'s cross-module dispatch of stats_duck's own struct-returning aggregates (`summary_stats` / `anova_oneway` / `chisq_independence`, called via an internal connection) hit a function-signature mismatch. `meta` / `lm` / `VISUALIZE` use built-ins or the parser and never make that call, so they stayed fine. Fixed by rebuilding the stats_duck WASM with `WASM_BIGINT=1`. Independently, `@duckdb/duckdb-wasm` is now pinned to the stable **`1.32.0`** (exact — dropping the `^` on the old `1.33.1-dev` nightly; `1.32.0` reports DuckDB v1.4.3), with the rebuilt extension bundled at `public/extensions/stats-duck/v1.4.3/wasm_eh/`.
- [Bug-fix] **`BedevereApp` applies the theme exclusively, so a host-set body class can't linger.** `setupTheme` / `setTheme` only *added* the active `theme-*` class to `<body>`; they never stripped a pre-existing one. An embedder that hardcodes a theme class for first-paint FOUC prevention (bedevere-desktop ships `<body class="theme-dark">`) kept that class forever — and because `_tokens.scss` orders `theme-dark` last, the cascade held every CSS-driven component on dark while the spreadsheet's own JS theme detector (which checks `theme-light` first) followed the real selection, so the two halves of the UI visibly disagreed (everything dark except the spreadsheet). Theme application now clears every theme variant before adding the active one (matching `/embed`'s `applyTheme`), so exactly one `theme-*` / `bedevere-app--*` class is ever present. Extracted as `themeClasses.applyThemeClasses` with a regression test.
- [Feature] **KoliStat "Statistical Report" restyle — Paper is the new default theme; themes become family × mode.** Bedevere takes on kolistat.com's "statistical report" identity so embeds read as kin to the page framing them: warm paper/ink surfaces, a booktabs result grid (heavy top/bottom rules, hairline rows, no vertical gridlines), IBM Plex Mono chrome, Source Serif 4 for prose, and duck-yellow `#ffd939` as the sole accent. Themes are now a two-axis **family × mode** choice — family `Paper` (new default) / `Tokyonight` (the former Day / Storm classics) / `Github` (the neutral `#f5f5f3` light + GitHub-Dark `#1f1f1f` palettes introduced earlier this cycle), mode `Light / Dark / Auto` — shown as two segmented controls in Settings → Theme. The six resolved variants (`theme-{light,dark,classic-light,classic-dark,github-light,github-dark}`) apply exclusively; persisted `light` / `dark` / `auto` migrate to Paper so existing users ride the restyle, while `classic-*` stays Tokyonight. `.theme` accepts a family, a mode, or a full variant. `/embed` gains additive `github-light` / `github-dark` values with every previous value still valid — `setTheme`, the embed URL params, and the postMessage contract are unchanged. App-wide structure: radius 0, flat ink rules instead of drop shadows, duck-chip active tabs, mono report buttons, ballot-box checkboxes / radios, monochrome `currentColor` icons (the duck logo stays), a 2px ink focus ring, and 10px scrollbars synced to the canvas grid. Charts get the "Field Notes" categorical ramp (duck → ink → four field hues) on mono axes. Fonts are self-hosted via `@fontsource` (IBM Plex Mono + Source Serif 4) — no runtime dependency on kolistat.com, keeping the WebView2 desktop host offline-clean; the serif face is Paper-only.
- [Feature] **`FileSource` wired into `ControlPanel` — the host-native file-open path is live.** The v0.13 `FileSource` scaffolding moved from interface to call sites: `ControlPanel`'s folder / file pickers now route through the injected `FileSource` (`pickFolder` / `pickFiles` / `openFolder` / `listFolderFiles` / `readFile`), branching to the host whenever the source isn't the browser File System Access API. The web app keeps the FSA path (`FsaFileSource`); bedevere-desktop injects `IpcFileSource`, so "Open Folder" pops the native OS dialog and the bytes stay on the host.
- [Security] **Embed prefill reads the URL fragment (`#…`), not the query string.** `/embed` now takes its `dataset` / `query` / `theme` / `autorun` / `id` params from the URL fragment when present, falling back to `?…` for older links. The fragment is never sent to the server, so a prefilled `query=<SQL>` no longer rides the request URL — sidestepping a cross-site XSS heuristic (NoScript's InjectionChecker) that flagged SQL-in-URL, and not leaking the query via the `Referer` header. The blog emits `#…` embeds.
- [Removed] **In-app feedback form + the Cloudflare feedback worker.** The Help panel's Feedback tab, the `FeedbackService` client, the `.feedback` command, and the D1-backed `cloudflare/feedback-worker/` are removed. Bug reports and contact now go through [kolistat.com/contact](https://kolistat.com/contact) (linked from the About tab); the `VITE_FEEDBACK_URL` build var is dropped.

## v0.13-i-am

- [Feature] **Pluggable Backend abstraction — BedevereApp is engine-agnostic.** The UI used to be hard-wired to `DuckDBService` (DuckDB-WASM in the browser). It now takes any implementation of a new `Backend` interface (`src/data/Backend.ts`) via `BedevereAppOptions.backend`. The default stays DuckDB-WASM so the standalone web app needs zero config; downstream embedders pass their own. The interface is engine-agnostic but DuckDB-flavored-SQL-shaped — `executeQuery` / `executeQueryAsDataProvider` / `executeQueryWithSchema`, `listTables` / `getTableInfo` / `listFunctions`, `registerFileURL` / `registerFileText` / `registerFileBuffer`, plus capability flags (`arrow`, `visualize`, `wipeUserState`, `dropByName`, `sas`, `spss`, `stata`) the UI checks before exposing the affordance. `BedevereApp`'s constructor drops its positional `duckDBService` arg in favour of `options.backend`; `runVisualize` and the format handlers + `FilteredDuckDBDataProvider` cascade to `Backend`. `SqlExecutor` stays exported as a structural alias for one release of NPM back-compat.
- [Feature] **`@kolistat/bedevere-wise/ipc` sub-entry — Bedevere Backend Protocol shipping ready-to-consume.** The full IPC stack that bedevere-desktop's renderer used to maintain locally moved into wise: `Bridge` (WebSocket + JSON RPC + Arrow IPC streaming framing), `IpcBackend` (implements `Backend` by routing every method to the Bridge), `IpcDataProvider` (DataProvider over Bridge), wire types for every RPC method + Plugin / License shapes. Host processes — the desktop's C++ shell today; a `pip install bedeverer-py` kernel, an R session, a remote relay tomorrow — drive the full Bedevere UI by speaking the v1.0 wire contract. The protocol spec moved to `docs/backend-protocol.md` (lifted from bedevere-desktop's `ipc-protocol.md`, generalized away from desktop-specific framing). `apache-arrow` joins the peer-deps; existing peer-deps gained `peerDependenciesMeta.optional: true` so hosts using only `/ipc` (no DuckDB-WASM, no CodeMirror) don't trip install warnings.
- [Feature] **`PersistenceBackend` abstraction.** `PersistenceService` used to write its kv slice (settings, environments, query bookmarks, the editor autosave draft, aliases, keymap overrides) straight to `window.localStorage`. It now takes a `PersistenceBackend` (`getItem` / `setItem` / `removeItem` / `keys` + optional `initialize` / `flush`) via `setBackend(...)`. The default is `LocalStoragePersistenceBackend` — same behaviour as before; hosts wanting a different substrate (the desktop's `IpcFilesystemPersistence` JSON file, a future server-synced account) substitute it before BedevereApp constructs. `IpcFilesystemPersistence` (exported from `/ipc`) hydrates from the host at boot via a new `loadPersistence` RPC, mirrors writes into an in-memory cache so reads stay synchronous, and debounce-flushes to the host via `savePersistence` (default 750 ms) — `flush()` forces an immediate save for `beforeunload` handlers. The IDB-backed paths (binary table snapshots, FSA folder handles) stay on IDB; they belong on the FileSource abstraction.
- [Feature] **`FileSource` abstraction (scaffolding).** A `FileSource` interface (`pickFolder` / `pickFiles` / `openFolder` / `listFolderFiles`) lifts the file-picker surface off ControlPanel so hosts with a native picker can substitute their own. `FsaFileSource` wraps the File System Access API (the existing web behaviour). `IpcFileSource` (exported from `/ipc`) proxies the picker to the host so the desktop renderer can hand off to Win32 IFileOpenDialog / NSOpenPanel / GTK4. ControlPanel's call sites haven't migrated yet — that lands in v0.14; the interface is locked here so the migration is mechanical and the desktop file-open path is ready to wire end-to-end as soon as the C++ pickers land.
- [Feature] **File export — `.export` writes whole tables to Parquet / JSON / SAS / SPSS.** The `.export` command gained binary/file formats alongside the existing clipboard-friendly text export (csv / tsv / html / markdown): `parquet` and `json` (DuckDB-native, any engine) plus `xpt` / `sav` / `por` / `sas7bdat` (stats_duck's COPY functions, offered only when `capabilities.visualize` reports stats_duck loaded). These run `COPY <table> TO …` against the dataset's backing table — the whole, typed table; active filters / sorts are a selection-export concern and aren't applied. A new optional `Backend.exportTable(opts)` carries it, engine-shaped on purpose: the in-process WASM engine (`DuckDBService`) COPYs to its virtual FS, reads the bytes back, and the UI downloads them; an out-of-process host (`IpcBackend`) pops a native Save dialog and runs the COPY itself, so the bytes never cross the wire (`{ kind: "bytes" | "saved" | "cancelled" }`). New wire method `exportTable` (params `table` / `format` / `filenameHint`; result `exported` / `cancelled` / `path` / `rowsExported`) with a Win32 `IFileSaveDialog` backing in the desktop shell. `DataProvider` gained an optional `getSourceTable()` so the command addresses the real relation rather than the display name. SAS7BDAT carries the stats_duck caveat — ReadStat's writer round-trips through ReadStat-family readers (this app, pyreadstat, haven, R) but real SAS won't open it; use `.xpt` for SAS-native files.
- [Enhanced] **Bundled stats_duck → v0.6.** The WASM extension under `public/extensions/stats-duck/v1.5.1/wasm_eh/` moves from v0.5 to the v0.6 build, which registers the `COPY … TO` writers (`xpt` / `sav` / `por` / `sas7bdat`) that back the new web-side file export. Pre-release build, pinned for this cycle.
- [Enhanced] **`PersistenceService` + singleton exported from the root entry.** Downstream embedders (the desktop renderer, future server-synced apps) can now `import { persistenceService } from "@kolistat/bedevere-wise"` and swap its backend during boot. `AppSettings` / `QueryBookmark` / `RecentFolderEntry` types come along for the ride.
- [Enhanced] **`BedevereApp` skips DuckDB-WASM extension probing when the backend isn't DuckDBService.** `DuckDBExtensionLoader` is WASM-specific (`INSTALL FROM URL` is a WASM-only concept); hosts that load extensions native-side surface what they got via `backend.capabilities.visualize` / `sas` / `spss` / `stata`. The Excel / Stat format handlers register only when the loader did, so an IPC backend without WASM Excel still boots cleanly.
- [Feature] **Chart rendering in <code>/embed</code>.** The embed route gains chart support — `VISUALIZE … DRAW` queries route through the same chart pipeline the main app uses, render via `ChartVisualizer`, and the iframe still reports its rendered height back to the parent. URL prefill (`?dataset=…&query=…`) covers chart queries without code changes. The chart pipeline pulls `vega-embed` lazily via dynamic import, so iframes that never render a chart pay zero bytes for it.
- [Feature] **NPM package split.** `@kolistat/bedevere-wise` exposes three entries: `/` (root, combined for back-compat), `/ui` (spreadsheet + column stats + chart + slim SQL editor + `DataProvider` interface + type helpers, no DuckDB-WASM dependency), and `/duckdb` (DuckDB-WASM service + DataProvider implementation). UI-only consumers (downstream tools that bring their own data layer — desktop, tlf-studio) can import from `/ui` without pulling in the Vite-specific `?url` worker imports of DuckDB-WASM.
- [Feature] **`runVisualize` exported helper.** The `VISUALIZE … DRAW` orchestration (parse spec + run each layer SQL + materialize datasets) lives in `src/data/visualize.ts` as a standalone helper, exported from `/ui` for downstream tools to drive the same pipeline against their own SQL executor. TabManager and the embed now both consume this single source of truth.
- [Enhanced] **Error / warning status-bar messages auto-expand the popover** — previously the popover only opened on click; now errors and warnings show their full text immediately. Success / info still stay collapsed.
- [Enhanced] **`/ui` and `/duckdb` shared via Vite chunks.** Common code (spreadsheet renderer, CodeMirror dialect, type helpers, Arrow unwrap) lives in shared chunks; the sub-entries are thin re-export shims.
- [Enhanced] **Library build hygiene.** `peerDependencies` declared for CodeMirror / Vega / DuckDB-WASM so consumers don't get duplicate copies. `sideEffects` marks the SCSS import so consumer tree-shakers don't strip the CSS bundle. `publishConfig.access: public` + `prepublishOnly: bun run build:lib` so `npm publish` works first-try. `engines.node: ">=18"` documents the minimum runtime. Unused `@codemirror/theme-one-dark` removed.
- [Enhanced] **README rewritten for the package audience.** App-focused intro moved to bedeverewise.app; the npm page now shows install + quick-start example + embedding-surface table + theming notes + bundler-compatibility note (Vite first-class, webpack works with `asset/resource`, esbuild/Parcel need plugin config).
- [Bug-fix] **`CREATE OR REPLACE TABLE` refreshes its open tab.** Re-running the statement now closes the existing tab and reopens fresh; the visualizer's cached rows used to paint over the new data otherwise.
- [Bug-fix] **`WITH … VISUALIZE` routes to the chart path.** CTE-wrapped `VISUALIZE … DRAW` queries used to fall through the SELECT classifier into the table-tab path where stats_duck's parser-extension hook never fired.
- [Bug-fix] **Embed initial-cells blank paint + dark-theme caret.** First paint now settles a layout frame before drawing; CodeMirror's blinking caret gets an explicit `caret-color` so it's visible against the dark Tokyonight background.
- [Removed] **Flaticon attribution from the About tab.** Paid Flaticon Premium license now covers the duck icon set; attribution is no longer required.

## v0.12-pull-the-other-one

- [Feature] **Environments.** Opening a folder auto-creates an environment named after that folder; the environment owns its datasets, its saved queries, and the workspace state (open data tabs + open query tabs + active tab). Switch via the dropdown above the file tree — closing the current env saves any drafts, swaps to the new env's datasets, and re-opens its workspace. Single-file drops register under a "default" env so casual imports don't bloat the list. Folder-handle binding survives renames so re-opening the same folder reuses its env. The shell mirrors the surface: `.env list | new <name> | switch <name> | rename <old> <new> | delete <name>`. State is JSON-serializable behind stable opaque ids, all writes go through the new `EnvironmentService`, and every persisted shape carries a schema version — the substrate for future server-sync and agent integrations.
- [Feature] **SQL editor tabs.** The single-document editor became a multi-tab editor. Each tab is a `.sql` "file" stored in the browser and owned by the active environment; new / close / rename / switch all live in the editor's own tab strip, distinct from the data/chart workspace tabs. Tab content autosaves on a 750 ms idle debounce per tab; reload restores exactly which tabs were open and which was active. Double-click a tab title to rename inline; Ctrl+S still writes the active tab's content to the named-bookmark store. The v0.11 single-slot `editorAutoSaveDraft` migrates to an untitled query in the default env on first launch.
- [Feature] **Auto-import small files + size warnings.** Drops below the size threshold (default 100 KB, configurable in Settings: 10 KB / 100 KB / 1 MB / never) import silently into DuckDB without opening a tab — convenient for ad-hoc joins where you don't want a tab for every file. Files at or above the threshold show a right-aligned size label (`12 KB`, `3.4 MB`) and a ⚠ glyph in the tree; clicking imports + opens. Folder scans (FSA picker) get the same treatment, with sizes populated lazily from the file handles.
- [Feature] **Failed-import → read-only text tab.** When a CSV / JSON / log file's import throws, the file opens as a read-only CodeMirror tab with the underlying DuckDB error banner-pinned above — so you can see the malformed row instead of just reading "could not parse" in a toast. Text-likeness is sniffed by extension first, then by a NULL-byte / non-printable scan. Binary files (e.g. PNG renamed to `.csv`) still fall through to the toast. Text tabs are ephemeral — closed on reload, not persisted into the workspace.
- [Feature] **`/embed` route — chromeless iframable Bedevere.** A separate Vite entry that renders just the editor + result panel, designed for embedding in writeups on a blog or doc site. URL prefill: `?dataset=<url>&query=<urlencoded-sql>&theme=light|dark&autorun=1&id=<opaque>`. Multiple `dataset=` params are allowed; each registers as a separate table (the file name and table name are intentionally different so the `read_*('<file>')` reference doesn't collide with the materialised table). The dataset has to be reachable by URL with permissive CORS — Bedevere doesn't host the bytes. postMessage protocol: child emits `{type:'embed-resize', height, id}` debounced 50 ms via ResizeObserver, parent sends `{type:'embed-theme', theme}` to flip themes without reload and `{type:'embed-run'}` to re-run the current query. Origin allowlist hard-codes the blog (caveofcaerbannog.com) and the standard dev ports; CSP `frame-ancestors` ships in `public/_headers` for the Workers static-asset route.
- [Feature] **Editor splitter resize + indent selector.** The horizontal split between editor and result is now draggable (drag handle in the editor's bottom border). The editor toolbar gained an indent dropdown (2 / 4 / Tab) that drives the `Tab` key behaviour. Settings persists both.
- [Enhanced] **Error and warning popovers auto-open.** Status-bar messages of severity `error` or `warning` now expand the popover automatically so the full text and any stack-trace details are visible without a click. Outside-click / Escape / close button dismiss as before, and the message's own duration timeout (10 s for errors, 6 s for warnings) still self-closes the popover. Success / info messages stay collapsed — they're short and self-contained.
- [Enhanced] **Bundled stats_duck bumped to v0.5.** The WASM binary committed under `public/extensions/stats-duck/v1.5.1/wasm_eh/` is now the v0.5 build of [the-stats-duck](https://github.com/KoliStat/the-stats-duck). Production deploys serve the WASM from the same Cloudflare origin; local dev follows the env-configured path.
- [Enhanced] **Self-hosted DuckDB worker JS.** The DuckDB-WASM worker is bundled into the app via Vite `?url` imports instead of fetched from jsDelivr at runtime — one fewer external dependency at boot, and the long-tail "jsDelivr blipped → reload fails with `importScripts` error" failure mode is gone. The WASM modules themselves still load from jsDelivr (they exceed Cloudflare Workers' per-asset cap).
- [Enhanced] **Saved Queries is per-environment.** The accordion reads from the active env's `queries` array; clicking an entry opens it as an editor tab (focuses the existing one if already open). Per-env grouping means folder-scoped queries don't pollute the default-env list and vice-versa.
- [Enhanced] **Tier 2 persistence pass.** `AliasManager` and `KeymapService` join the rest of the localStorage callers behind `PersistenceService` — all storage writes now flow through one typed surface, the substrate for the env-storage envelope and a future server-sync layer.
- [Enhanced] **Dialog base class.** `HideColumnsDialog`, `HtmlPasteDialog`, and `SaveQueryDialog` extracted shared overlay / focus-trap / escape-key behaviour into a `Dialog` base; the accent colours align across the three so they read as the same family.
- [Enhanced] **HelpPanel split.** The tutorial markup, format-preset table, and About HTML moved into their own modules under `HelpPanel/`. The component stays focused on lifecycle and tab switching; release-day "refresh About" edits touch one small file instead of the umbrella component.
- [Enhanced] **DuckDB wipe on env switch.** Switching environments drops the previous env's tables before registering the new env's files, so a `result_1` from one workspace can't be queried out of the next one — keeps the SQL surface honest about what's actually loaded.
- [Bug-fix] **`CREATE OR REPLACE TABLE` refreshes its open tab.** Re-running a `CREATE OR REPLACE TABLE foo AS …` script while `foo` was already open used to leave the spreadsheet painting cached rows from the previous version — DuckDB had the new data, but the visualizer's row cache and the provider's parsed-types cache were still bound to the old schema. The dispatcher now closes the existing tab and re-opens fresh, so the new rows always show. Scroll position / selection / local filter+sort don't survive the rebuild yet; an in-place refresh is on the v0.13 list.
- [Bug-fix] **`WITH … VISUALIZE` routes to the chart path.** Queries that wrapped `VISUALIZE … DRAW` in a CTE used to fall through the SELECT classifier into the table-tab path, where stats_duck's parser-extension hook never fired. The dispatch now scans past leading `WITH` blocks before classifying — CTE-wrapped charts render.
- [Bug-fix] **Spreadsheet's last row is reachable again.** The scroll spacer underestimated the row-snap delta, so on long datasets the final row would sit just past the scrollable extent. Spacer height now includes the snap delta; you can scroll to (and select) the last row.
- [Bug-fix] **Row-snap aligns the viewport.** Vertical scrolling now snaps to row boundaries instead of leaving rows half-clipped at the top of the visible area. Programmatic scrolls (cell navigation, "go to row N") snap into the same grid.
- [Bug-fix] **`pushRecentFolder` reuses the same IDB id.** Re-picking a folder with the same name no longer leaves orphaned `folder_handles` rows in IndexedDB — the recent-folders list resolves to one stable id per folder.
- [Bug-fix] **Embed: initial-paint blank-cells / dark-theme caret.** The result panel forced a layout settle (one `requestAnimationFrame` + `resize`) after the visualizer initialises so cells render on first paint instead of waiting for a scroll/theme nudge. CodeMirror's blinking caret got an explicit `caret-color` so it's visible against the dark Tokyonight background.

## v0.11-sovereign-of-all-england

- [Feature] **Hide / show columns.** New `.hide` shell command opens a dialog with checkboxes for every column plus Show-all / Hide-all bulk toggles and a filter search. State persists per dataset and restores when you reopen the file. Filter and sort still operate on hidden columns by name — unhiding restores the previous filter / sort state automatically. Right-click a header for the same "Hide column" item.
- [Feature] **Drag-to-reorder columns.** Press and hold on a column header (past the sort-arrow zone), drag past a 4 px threshold, and a faint ghost follows the cursor with a vertical blue drop-indicator showing where the column will land. Release commits the new order; plain clicks still select the column. The order persists per dataset alongside hide / sort / filter.
- [Feature] **Right-click context menu on the spreadsheet.** Header right-click → Sort asc / desc / Clear sort / Hide column. Cell right-click → Copy / Inspect (for complex cells) / Sort by column / Hide column. Row-gutter right-click → Copy row. The menu is zone-aware so the items match where you clicked.
- [Feature] **Editor autosaves while you type, restores on reload.** The SQL editor's contents are flushed to localStorage on a 750 ms idle debounce — short enough that a browser crash or refresh loses essentially nothing, long enough that we're not pummeling storage on every keystroke. Reloading the app drops you back into the same query you were working on, and the editor opens automatically if there's a restored draft. The named-bookmark store (`.query save <name>`) is unchanged; this is a separate, single-slot working draft.
- [Feature] **Ctrl+S in the editor → "Save query as…" dialog.** Single-input modal that writes the current query to the named-bookmark store. The placeholder shows an example name; the dialog warns when the typed name would overwrite an existing bookmark (the save still proceeds — same semantics as `.query save`).
